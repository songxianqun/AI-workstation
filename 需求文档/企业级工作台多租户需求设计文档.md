## 一、需求背景

产品定位为**企业级自动驾驶操作系统的工作台**，当前核心诉求已从"做项目"转向"卖产品"，需要以标准化 SaaS 产品形态对外交付。领导（张洵）明确的总体策略是：

- **先跑通再优化**：用最简流程快速搭建业务框架，避免前期过度设计；
- **开箱即用**：企业用户注册后直接开干，无需复杂后台配置，把运维成本降到最低；
- **商业闭环前置**：计费、账单、付费入口在产品规划阶段即纳入设计。

---

## 二、需求目标

1. **多租户开箱即用**：支持企业自助注册开通租户，注册后自动分配 Token 与算力资源，无需人工配置即可使用。
2. **租户彻底隔离**：租户与租户之间（如 A 企业与 B 企业）数据、文件、会话完全隔离，杜绝跨租户信息泄露。
3. **极简权限模型**：初期仅区分"管理员"与"普通用户"两种角色（开关模式），降低新企业接入门槛，不做复杂权限区分。
4. **低门槛成员扩充**：管理员通过邀请链接 / 二维码邀请员工扫码注册并加入机构，快速完成组织搭建。
5. **商业化闭环**：集成计费系统，支持 Token 计费或余额模式，用户可在工作台查看用量、余额，并提供便捷付费入口。

## 三、需求拆解分析

### 3.1 租户体系与数据隔离

| 分析项 | 结论 / 决策 | 来源 |
| --- | --- | --- |
| 租户间关联性 | **彻底隔离**，租户间无业务关联 | 张洵拍板 |
| 租户开通方式 | 企业**自助注册**，系统自动开通租户并分配资源 | 张洵 |
| 隔离范围 | 会话、文件、成员、用量账单等全部业务数据按租户隔离 | 会议共识 |
| 风险点 | 文件权限控制不当可能导致跨租户信息泄露，需在方案中重点防控 | 宋贤群提出 |

**拆解要点**：
- 所有业务数据模型需携带租户标识，接口层做强制租户过滤；
- 用户与租户的关系：现阶段按"一人一组织"简化处理（"一个人会不会多组织"在会上未展开，列入待确认项）；
- 文件/会话的可见性控制在租户内部也需有基本边界（见 3.2）。

### 3.2 权限模型

| 角色 | 权限 |
| --- | --- |
| 管理员 | 邀请成员、管理原子模型空间（维护入口）、查看/管理租户账单与付费 + 全部普通功能 |
| 普通用户 | 会话、文件等基本使用权限 |

**决策要点**：
- 初期采用**简化模型（开关模式）**：仅"管理员 / 普通用户"两角色，剥离复杂邀请权限；
- 管理员与普通用户在**会话、文件等常规功能上权限一致**，不做复杂区分（张洵拍板）；
- 管理员额外保留：成员邀请、原子模型空间维护、计费管理等管理侧能力；
- 后续迭代再评估细粒度权限（如文件可见性分级、多管理员等）。

### 3.3 用户注册与邀请机制

**核心流程**：

```
机构管理员生成邀请链接/二维码 → 员工扫码 → 注册账号 → 自动加入机构 → 系统自动分配 Token/算力 → 直接使用
```

**拆解要点**：
- 注册后即可使用，无需后台审批配置（开箱即用）；
- 现状为"邀请链接点击即加入"，会议结论指出**存在安全隐患，邀请机制需补充身份验证**（如链接有效期、验证码、管理员确认等，具体方式待设计确认）；
- 邀请链接与二维码两种载体均需支持；
- 对外邀请页（员工扫码落地页）仅展示邀请人姓名与机构信息，**不标注邀请人角色**（如"管理员"），角色标识仅在租户内部界面体现。

### 3.4 资源分配与商业化计费

**拆解要点**：
- 新用户注册后**自动分配 Token 与算力资源**，底层资源分配做成无感体验；
- 必须集成计费系统，支持两种模式：**Token 计费**或**余额模式**；
- 工作台界面需展示：**用量、余额**；
- 增设**账单与付费（充值）入口**，实现商业闭环。

**原型定稿交互（V1.1）**：
- **用量入口**：位于左下角用户栏铃铛图标左侧（仪表盘图标），**悬停**浮出迷你用量卡片（个人用量进度条 + "查看详情"链接）；管理员浮窗额外含"用量管理"入口，直达成员管理；
- **计费中心**：三个 Tab —— 我的用量（全员）/ 成员管理（管理员）/ 消费账单（管理员），头部提供充值按钮（管理员）；
- **我的用量**：套餐内 Token 用量进度、近 7 日用量趋势、用量明细列表；
- **角色差异**：成员视角仅展示个人用量，**不展示机构余额**及任何账单信息；管理员视角额外可见机构余额卡片（含立即充值）、成员 Token 消耗排行、账单明细与下载；
- **充值流程**：充值弹窗内选择金额与支付方式，完成后余额即时更新；
- **权限标签原则**：界面上不出现"仅管理员"类文字标签，管理侧能力仅通过入口显隐体现。

### 3.5 原子模型空间（外部系统入口）

**拆解要点**：
- 原子模型空间为**外部系统**，现阶段维护不在本系统，工作台内**仅做展示 + 入口跳转**；
- 入口集成在**侧边栏**（"任务"导航下方），通过打通账户系统实现**无感跳转（免登）**；
- 维护权限仅归属管理员；
- 定位为"套壳"策略：用轻量入口快速拼装能力，避免底层重复造轮子。

**原型定稿交互（V1.1）**：
- 点击"原子模型"入口后**在新标签页打开原子模型库页面**（不覆盖工作台、不做 iframe 内嵌），落地页直接展示已发布公开原子模型的**设计、维度与要素**，全员可用；
- "管理模型"（AI 绘画设计自己的原子模型）与"蒸馏模型"（从同类原子模型蒸馏业务模型）等功能入口由**原子模型系统内部提供**，工作台侧不重复建设；
- 免登由账户体系打通后无感实现，界面上**不展示"免登/SSO"类标记**。

### 3.6 数据安全与泄露防控

**拆解要点**：
- 跨租户：接口与存储层双重租户隔离校验；
- 租户内：文件权限需有基本控制，防止权限控制不当导致信息泄露；
- 邀请环节：补充身份验证，防止邀请链接扩散导致陌生人混入租户；
- 普通用户会话/文件的可见性控制规则需在界面设计阶段明确（默认建议：个人数据仅本人可见）。

## 五、界面设计指引（已按高保真原型定稿）

基于以上功能清单，页面/界面模块设计如下（详见原型 `tenant-invite-register-design.html`）：

1. **注册/开通流程页**：企业自助注册 → 租户开通成功 → 引导进入工作台（体现"开箱即用"）；
2. **邀请成员弹窗/页面**：邀请链接复制 + 二维码展示，含身份验证设置项（管理员视角）；
3. **员工加入流程页**：扫码落地页（邀请信息不标注邀请人角色）→ 注册 → 加入成功进入工作台（员工视角）；
4. **成员管理页**：并入计费中心"成员管理"Tab —— 成员列表、角色标识、成员 Token 消耗、移除/设角色操作；
5. **计费中心页**：跨中栏+右栏覆盖面板，Tab 结构（我的用量/成员管理/消费账单）+ 充值弹窗；成员视角仅"我的用量"（无机构余额）；
6. **侧边栏**："任务"导航下方原子模型入口（点击新标签页打开模型库）；左下角用户栏内用量悬停入口（铃铛左侧）+ 消息通知铃铛；"邀请成员加入机构"入口位于用户栏上方；
7. **管理员/普通用户视角差异**：仅通过管理侧入口（邀请、用量管理、机构余额、账单、充值）的显隐体现，**界面不出现"仅管理员"文字标签**，常规功能界面两角色保持一致。
