# 左侧工作空间优化方案（终稿）

> 结合：① 领导 2026-07-29 会议关于 `workspace` 字段的指导意见；② 测试记录中左侧/工作空间相关 9 条问题；③ 当前产品现状。
> 整理时间：2026-07-30

---

## 一、指导思想

1. **工作空间是唯一主体**：左侧面板以"工作空间"为单一组织单元，取消"最近"、"动态"、"通知"等平行入口。
2. **会话必须归属工作空间**：任何会话（用户新建、任务产生、自动化/订阅产生）都必须落入某个工作空间，不存在游离会话。
3. **按最新会话时间排序工作空间**：哪个工作空间下的会话最新活跃，该工作空间就排在最前面。
4. **默认工作空间兜底**：仅保留一个系统默认工作空间"我的会话"，承载未指定/未归类的会话。
5. **任务/自动化通过 `workspace` 字段指明归属**：这是领导会议确定的核心数据结构改造。

## 三、排序规则

### 3.1 工作空间排序
按该工作空间下**最近一条消息的时间**倒序排列。

> 例：项目 A 下会话 X 刚产生新消息 → 项目 A 排到最顶；客户跟进 30 分钟无新消息 → 排在项目 A 下方。

### 3.2 工作空间内会话排序
按该会话**最近一条消息的时间**倒序排列。

### 3.3 置顶 override
- 置顶的工作空间：排在"工作空间"区最上方
- 置顶的会话：统一放在"📌 置顶"区（跨空间快捷入口），不占工作空间内部位置

### 3.4 默认展示策略
- 默认展开 **3~5 个**最活跃的工作空间
- 每个工作空间默认展示 **2~3 条**最近活跃的会话
- 超出部分折叠：点击工作空间底部的"**更多**"向下展开剩余工作空间
- 点击标题右侧"**全部**"打开右侧面板查看全量

## 四、会话归属规则（核心改造）

### 4.1 用户新建会话

| 场景 | 归属规则 |
|---|---|
| 用户在某个工作空间内点击"新建会话" | 直接放入该工作空间 |
| 用户在全局入口点击"新建会话"，未指定工作空间 | 放入系统默认工作空间 **"我的会话"** |
| 用户后续手动拖拽/移动 | 可从"我的会话"迁移到任意自建工作空间 |

### 4.2 任务产生的会话（领导会议核心）

在任务/自动化数据库中增加 **`workspace` 字段**，允许两种状态：**指明** 或 **缺省**。

#### 指明场景
- 任务创建时 `workspace` 填了具体工作空间名称
- 系统先按名称查找对应工作空间
  - 找到 → 该任务相关会话放入该工作空间
  - 未找到 → 新建同名工作空间，再放入
- 创建任务的 Skill 应根据当前上下文（用户当前所在工作空间）自动填充该字段

#### 缺省场景（当前优先级更高）

| 任务类型 | 归属规则 |
|---|---|
| **单人任务** | 推送到系统默认工作空间 **"我的会话"** |
| **多人/协同任务** | 按任务名创建一个协同工作空间，任务相关会话放入该空间 |

> 核心原则：避免"10 个任务 = 10 个空文件夹"的爆炸问题。单人任务集中到一个默认空间，只有真正的协同任务才新建空间。

### 4.3 自动化 / 订阅产生的会话

同样支持 `workspace` 字段：

| 场景 | 归属规则 |
|---|---|
| 自动化/订阅创建时指明了 `workspace` | 会话放入指定工作空间 |
| 自动化/订阅未指明 `workspace` | 以自动化/订阅名称为单位创建一个工作空间，该自动化/订阅下所有会话放入该空间 |

> 例："每日简报"自动化未指定 workspace → 创建"每日简报"工作空间，所有每日简报会话都在该空间下，不再为每次触发单独建文件夹。

### 4.4 共享会话

- 别人把某个工作空间共享给我 → 我获得该工作空间的访问权
- 该共享工作空间按活跃排序自然上浮
- 协作 @ 我的消息通过该工作空间内的红点/徽章/@标识触达

## 五、系统默认工作空间"我的会话"

| 属性 | 说明 |
|---|---|
| 命名 | "我的会话"（可配置，可改名如"临时"、"默认"） |
| 性质 | 唯一系统级工作空间，不可删除 |
| 用途 | 承载：① 随手创建未归类的会话 ② 单人任务产生的会话 ③ 未指明 workspace 的自动化/订阅（如果产品决定不为其单独建空间） |
| 排序 | 与其他工作空间一视同仁，按最新会话时间排序 |
| 管理 | 用户可手动将其中会话迁移到自建工作空间 |

## 七、新消息提醒

| 场景 | 提醒形式 |
|---|---|
| 工作空间内有会话收到新消息 | 工作空间条目显示未读数红点 |
| 会话内有人 @ 我 | 会话条目显示 "@我" 徽章 + 蓝边高亮 |
| 自动化/订阅在工作空间内产生新会话 | 对应工作空间红点 + 新会话标记 |
| 任务状态变更 | 通过任务中心通知，不污染工作空间列表 |

## 八、与既有问题的对应修复

| 既有问题 | 本方案解法 |
|---|---|
| 缺少科学的折叠机制 | 默认只展示 3~5 个活跃工作空间；右侧面板承载全量；7 天无消息可自动沉底/归档 |
| 会话标题过长 | AI 自动摘要 ≤20 字，超出"..." + 悬停显示完整 |
| 缺少会话置顶 | 新增 📌 置顶区，支持置顶工作空间和置顶会话 |
| 系统自动创建多余会话 | 任务/自动化通过 `workspace` 字段统一归属，不再随意新建空间 |
| 历史会话内容不同步 / 问题重复 | 数据层统一治理：消息以服务端为准，本地缓存同步 |
| 新建会话时不能就地新建文件夹 | 新会话默认进"我的会话"，用户可后续拖拽/移动到目标空间；或在工作空间内直接新建 |
| 工作空间文件夹级创建会话按钮无效 | 保留该按钮，点击后新会话直接放入该工作空间 |

## 九、落地阶段

### Phase 1：数据结构改造（1~2 周）
- 任务/自动化数据库增加 `workspace` 字段
- 明确"指明"和"缺省"两种状态的处理逻辑
- 先打通缺省路径：单人任务 → "我的会话"，多人任务 → 按任务名创建协同空间

### Phase 2：左侧面板重构（2~3 周）
- 取消"默认文件夹"、"自动化文件夹"、"订阅文件夹"等系统文件夹
- 上线单一"工作空间"区域
- 实现"按最新会话时间排序工作空间" + "工作空间内按最新会话时间排序"
- 默认只展示 Top 3~5 工作空间

### Phase 3：Skill 上下文感知（3~4 周）
- 创建任务/自动化的 Skill 根据用户当前所在工作空间自动填充 `workspace` 字段
- 用户可在创建时手动修改/选择目标工作空间

### Phase 4：右侧面板 + 长期优化（持续）
- 上线右侧面板"全部工作空间"视图
- AI 标题摘要、数据一致性治理、归档策略

## 十、关键指标预期

| 指标 | 当前 | 优化后 |
|---|---|---|
| 左侧平均文件夹数 | 20+ | ≤ 5（默认展示） |
| 找到目标会话点击次数 | 3~5 次 | 1~2 次 |
| "一个任务一个文件夹"现象 | 普遍 | 单人任务集中，仅协同任务新建空间 |
| 新消息感知率 | 低 | 高（工作空间红点 + @我徽章） |

---

## 十一、一句话总结

> **左侧面板以"工作空间"为唯一主体，所有会话必须归属工作空间；工作空间按最新会话时间排序，默认只展示 3~5 个最活跃空间；任务/自动化通过新增 `workspace` 字段指明归属，单人任务/未指明任务集中放入系统默认"我的会话"，避免文件夹爆炸；想看全量进入右侧面板。**
