# 会话摘要功能方案

## 1. 功能定位

会话摘要不是聊天记录压缩，也不是个人笔记，而是协作会话内全员共用的一份动态工作状态。它的核心目标是：让进入或回答这个会话的成员，通过右侧“会话目录”一眼知道会话在做什么、当前进展、已完成与待推进事项，以及已形成的关键结论。

适用于多人讨论、AI 协同产出、方案评审、任务推进、异常处理和新成员加入等场景。

## 2. 核心原则

1. **一会话一份共享摘要**：所有参与成员看到同一份工作状态，避免出现不同版本的团队共识。
2. **内容共享、展示个性化**：摘要内容、更新时间和更新结果全员共享；每个用户独立决定展开或收起。
3. **后台自动更新为主，手动更新为补充**：系统在合适时机自动检查与更新；成员可随时点击“更新摘要”立即刷新。
4. **人员确认优先**：AI 建议只有被成员明确采纳后，才可写入已完成或已确认结论。
5. **突出工作变化**：摘要提取完成项、待推进、结论、负责人、时间节点和阻塞，不复述闲聊与 AI 思考过程。
6. **资料可追溯**：右侧目录保留来源，供成员快速查看本会话中用户上传的文件、图片等资料。

## 3. 页面位置与交互

摘要放在右侧“会话目录”顶部；下方按现有目录结构展示当前任务、协作智能体、成果物和来源。

```text
会话目录
├─ 会话摘要                                      [收起]
│  更新于 今天 10:20 · 自动更新
│  这是什么工作 / 当前进展 / 已完成 / 待推进 / 关键结论
├─ 当前任务
├─ 协作智能体
├─ 成果物
└─ 来源
   ├─ 用户上传的文件
   ├─ 用户上传的图片
   └─ 其他附加到会话的资料
```

- 默认展开摘要；点击“收起”后，当前任务及以下模块自动上移。
- 收起状态仅影响当前用户，其他成员仍按自己的状态展示；再次进入会话时保持上次状态。
- 摘要发生实质更新但用户当前收起时，标题显示“有更新”提示。
- “来源”用于展示原始资料，不与“成果物”混淆：成果物是会话协作产出的方案、文档、任务等；来源是用户带入会话、供讨论参考的文件、图片及其他附件。
- 每条来源展示缩略图或文件类型图标、名称、上传人、上传时间和“已附加到对话”状态；点击可预览或打开原始资料。

## 4. 摘要内容结构

### 4.1 这是什么工作

用一句话描述当前会话的工作目标。

推荐格式：`推进【工作对象】，完成【核心交付物】，用于【业务目标】。`

示例：推进 630 版本工作台改造，完成 Rclaw 接入方案及相关业务场景的演示准备。

### 4.2 当前进展

说明当前阶段、最新进展、正在推进的重点和明确阻塞。

示例：技术方案已经完成，当前正在确认 Rclaw 接入方式、接口权限和演示范围。

### 4.3 已完成

仅记录明确完成、提交、确认或采纳的事项。

```text
✓ 完成 Rclaw 技术方案初稿
✓ 完成酒店和酒交业务场景梳理
✓ 已生成 B 端工作台半成果演示方案
```

### 4.4 待推进

记录尚未完成、待确认、进行中、待补充或受阻的事项。

```text
○ 确认 Rclaw 最终接入方式      待确认
○ 完成演示环境部署               进行中
○ 开通接口测试权限               受阻
```

### 4.5 关键结论

展示方案、范围、分工或时间节点等重要判断，并标明提出人和确认状态。状态包括：个人观点、待确认、已确认。

AI 自身的建议不能直接成为“已确认结论”。只有成员明确表达“确认按方案 A 执行”“大家一致同意”等语义后，才可以更新为已确认结论。

## 5. 自动更新、手动更新与新鲜度

### 5.1 更新机制

以后台自动更新为主，成员手动更新作为即时补充：

| 机制 | 触发时机 | 行为 |
|---|---|---|
| 首次生成 | 协作会话创建后，产生首条有效工作信息 | 后台生成首份摘要 |
| 消息合并更新 | 产生有效新消息后，等待短暂合并窗口（如 1–3 分钟） | 避免每条消息都生成，集中检查新增内容 |
| AI 任务完成 | AI 输出结果且成员采纳，或产出成果物 | 后台优先检查摘要 |
| 关键工作事件 | 完成、结论确认、负责人/截止时间/阻塞变化 | 后台优先检查摘要 |
| 手动更新 | 任一成员点击“更新摘要” | 跳过等待，立即检查截至当前的新增内容 |

同一会话同一时刻只允许一个更新任务。自动任务执行中，手动点击显示“正在更新”；若有更新任务排队，以最新消息范围合并处理。

### 5.2 状态展示

摘要只显示一个时间：最近一次摘要检查完成时间。自动检查完成后直接更新该时间；手动检查也同样刷新时间。

| 状态 | 展示文案 | 说明 |
|---|---|---|
| 首次生成 | 生成于 今天 10:20 | 首份摘要已生成 |
| 等待自动处理 | 更新于 今天 10:20 · 有新消息待更新 | 有新消息，后台将在合并窗口后处理 |
| 检查中 | 正在更新摘要… | 自动或手动任务执行中 |
| 自动有效更新 | 更新于 今天 11:05 · 已自动更新 | 摘要内容已变化 |
| 自动无有效更新 | 更新于 今天 11:05 · 已自动检查 | 内容无变化，仅更新时间刷新 |
| 手动有效更新 | 更新于 今天 11:05 · 本次有内容更新 | 成员主动触发且内容已变化 |
| 手动无有效更新 | 更新于 今天 11:05 · 本次无内容更新 | 成员主动触发，内容无变化 |

“本次有内容更新/本次无内容更新”只在手动触发后展示；后续有新消息时，状态恢复为“有新消息待更新”。

## 6. 更新流程与内容规则

```text
自动事件或成员点击“更新摘要”
→ 检查是否已有更新任务
→ 读取上次摘要覆盖消息后的新增消息、关联成果物和来源资料
→ 区分成员消息、AI 消息、系统消息和上传资料
→ 提取有效工作事件，并与当前摘要对比
→ 有变化：更新共享摘要并同步全员
→ 无变化：保留原摘要，刷新检查时间
```

本期不提供更新预览、人工编辑、是否更新确认和保留旧摘要选择。

### 6.1 需要更新的变化

- 形成新结论或调整已有结论。
- 完成、提交或确认了一项工作。
- 新增待推进事项，或待推进状态变化。
- 新增负责人、截止时间、风险或阻塞。
- AI 结果被成员明确采纳。
- 新增成果物且成员确认其工作用途。
- 新增来源资料，并被成员引用、讨论或明确作为决策/产出的依据。

### 6.2 不需要更新的内容

- 寒暄、简单确认和重复讨论。
- “收到”“好的”“没问题”等消息。
- 未被成员采纳的 AI 建议。
- 与当前工作无关的信息。
- 只上传文件、图片等来源资料，但未形成明确讨论、结论或工作结果。
- AI 思考过程和重复解释。

## 7. 不同场景的总结规则

| 会话场景 | 总结重点 | 不应写入摘要 |
|---|---|---|
| AI 回复较多 | 最终产出、被采纳建议、成果物、风险和待确认事项 | AI 思考过程、重复解释、未采纳建议 |
| 成员聊天较多 | 共识、分歧、负责人、时间节点和阻塞项 | “收到”“好的”等确认性消息 |
| 人员聊天与 AI 混合 | 以成员最终确认为准；AI 结果被采纳后才进入完成项或结论 | 将 AI 单方建议写成已确认结论 |
| 头脑风暴 | 候选方案、优缺点和未决问题 | 将候选方案写成最终决定 |
| 异常或阻塞 | 阻塞原因、影响范围和处理责任人 | 不影响工作推进的普通讨论 |
| 来源资料较多 | 被引用资料、资料用途，以及其支持的结论/产出 | 单纯罗列文件名或未使用的附件 |

## 8. 数据模型

### 8.1 共享会话摘要

```text
conversation_summary
├─ conversation_id
├─ work_description
├─ current_progress
├─ completed_items
├─ pending_items
├─ key_conclusions
├─ version
├─ covered_message_id
├─ last_checked_at
├─ last_update_result
├─ last_update_mode          // auto | manual
└─ last_triggered_by
```

`last_update_result` 取值：`generated`、`content_updated`、`no_content_update`。

### 8.2 用户视图状态

```text
conversation_summary_view_state
├─ user_id
├─ conversation_id
├─ is_collapsed
├─ last_seen_summary_version
└─ updated_at
```

### 8.3 来源资料

```text
conversation_source
├─ source_id
├─ conversation_id
├─ type                      // file | image | link | other
├─ name
├─ preview_url
├─ original_url
├─ uploaded_by
├─ uploaded_at
├─ attachment_message_id
└─ status                    // attached_to_conversation
```

## 9. 本期范围

### 本期实现

- 一会话一份共享摘要。
- 会话目录顶部展示摘要，个人可收起/展开。
- 工作说明、当前进展、已完成、待推进、关键结论五个固定模块。
- 后台自动生成与事件/消息合并更新；成员可手动立即更新。
- 自动更新和手动更新的状态区分。
- 同一时刻只执行一个摘要更新任务。
- AI 按不同会话场景提取最关键的工作信息。
- 会话目录在成果物下展示“来源”，沉淀用户上传的文件、图片等资料。

### 后续实现

- 摘要版本历史与变更记录。
- 待推进事项一键转任务。
- 成员确认关键结论。
- 跨会话和跨工作空间调用摘要。
- 基于角色的“与我相关”摘要视图。

## 10. 验收标准

1. 同一协作会话的成员看到相同摘要内容；收起状态不影响其他成员。
2. 摘要默认展开，收起后当前任务、协作智能体、成果物和来源自动上移。
3. 新成员进入会话时，无需手动生成即可看到后台已生成的最新摘要。
4. 有新增消息后，系统在合并窗口内自动检查摘要；重要工作事件可优先检查。
5. 任一成员可手动更新摘要，并在当前更新周期内看到本次更新结果。
6. 无内容更新时，摘要内容不变但更新时间刷新。
7. 未经成员确认的 AI 建议不能成为已确认结论。
8. 来源可展示用户上传的文件、图片等资料，并可打开原始资料；来源与成果物语义清晰区分。
9. AI 回复较多、成员聊天较多、混合会话和资料密集会话均能突出关键工作信息。
